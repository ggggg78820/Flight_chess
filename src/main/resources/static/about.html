資料庫驗證概念

展示模型與實際資料對應

表格本展示對應資料用途
usersplayer1、勝敗統計使用者與總勝敗
gamesresult、turn_count、used_tower_count遊戲紀錄
towers砲塔、冰霧塔、雷達塔塔種資料
game_towers某局在 A05 / C12 等塔位放了哪種塔串接 games 與 towers
資料表關聯 users (1) ──< games (1) ──< game_towers >── (1) towers
一個 users 可以對應多筆 games（一個玩家打很多局）；一筆 games 可以對應多筆 game_towers（一局裡建了好幾座塔）； 一種 towers 也可以出現在很多筆 game_towers 裡（同一種塔在很多局裡都被用過）。
後端分層 Controller（處理 HTTP 細節）→ Service（帳密驗證、遊戲規則驗證、資料組裝）→ Repository（Spring Data JPA，跟資料庫溝通）。登入狀態用 HttpSession 管理，需要登入的 API 一律從 session 讀出使用者身分，不接受前端宣稱的任何使用者 id。
想看完整的 API 清單、建置與展示步驟？請看專案原始碼根目錄的 README.md。
